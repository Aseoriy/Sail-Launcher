# Sail Launcher v5.3 account and portable cloud setup

The launcher code intentionally contains no Dropbox or Google client secret. Portable provider connections are brokered by Supabase Edge Functions, and refresh tokens are encrypted through Supabase Vault.

## Provider dashboards

Register this exact production redirect URI in both the Sail Dropbox app and the current Google Drive test app:

```text
https://vglpzpffejwgttlqrums.supabase.co/functions/v1/cloud-oauth-callback
```

For Dropbox, enable these scoped permissions:

- `account_info.read`
- `files.content.read`
- `files.content.write`
- `files.metadata.read`

Enable refresh tokens/offline access. Normal launcher users do not enter Dropbox credentials; they sign in to Sail and select **Link Account**.

OneDrive is custom-app-only. Users who want it must register their own Microsoft app and use the existing custom client-key panel.

## Supabase secrets

Set these values in the Supabase project’s Edge Function secrets. Use the Dropbox app values already supplied privately and the existing Google test-app values while the replacement Google app is under review.

```text
DROPBOX_CLIENT_ID
DROPBOX_CLIENT_SECRET
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
```

Do not add the values to `.env` files that are committed, source code, release notes, or the Electron package.

## Deployment order

1. Set the four Edge Function secrets.
2. Deploy `account-login`, `account-update-username`, `account-update-password`, `account-delete`, `cloud-oauth-start`, `cloud-oauth-callback`, `cloud-access-token`, and `cloud-disconnect`.
3. In **Authentication → Email Templates → Magic Link**, publish `supabase/templates/sail_verification.html`. It intentionally includes both `{{ .Token }}` for the launcher's mandatory code check and `{{ .ConfirmationURL }}` for Sail Hub's verified-link flow. Keep the project's email OTP length set to 8 digits.
4. Publish the updated Sail Hub pages so username login uses `account-login`.
5. Apply `supabase/migrations/20260723010000_sail_accounts_sync_v2.sql`.
6. Apply the account-management and account-sync index migrations that follow it.
7. Style the Reset Password, Reauthentication, and Password Changed Supabase Auth templates.
8. Test email login, username login, avatar upload, verified account changes, Dropbox connect/disconnect, Google connect/disconnect, refresh after token expiry, and a second-PC profile import.
9. Release the v5.3.0 launcher installer.

The migration removes the legacy public `profiles.email` column. Do not apply it before the updated website login code and `account-login` function are deployed.
